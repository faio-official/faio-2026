## 1. Легенда

В кабинете сидят два человека. Один пишет программу, а другой пишет статью. Их экраны не видны, и всё, что можно услышать — это звуки клавиатур.

Сможете ли вы определить, кто чем занимается?

В этом задании вам предстоит выяснить, содержат ли звуки нажатия клавиш достаточно информации, чтобы отличить написание кода от обычного набора текста.

## 2. Формальная постановка задачи

Каждая строка в наборе данных `train_labels.csv` соответствует **одной записи работы человека с клавиатурой** продолжительностью около 20 секунд. Она содержит идентификатор аудиофайла (хранящегося в директории `train/`) и истинную метку: `coding` (программирование) или `writing` (письмо/набор текста).

Для каждого аудиофайла в директории `test/` необходимо спрогнозировать характер работы с клавиатурой и присвоить ему метку `coding` или `writing`.

Обратите внимание, что эти два вида деятельности представлены **неодинаковым** количеством аудиофайлов как в обучающих, так и в тестовых данных.

## 3. Входные данные

Файл `train_labels.csv` содержит следующие столбцы.

- `id` — идентификатор аудиофайла.
- `target` — `coding` или `writing`, настоящая метка для аудиофайла.

Файла `test.csv` **нет**.

## 4. Выходные данные

Участники должны отправить CSV-файл с названием **solution.csv**, имеющий следующий формат:

```
id,target
0,writing
1,coding
2,writing
...
```

`target` — это предсказанная вами метка: `coding` либо `writing`. Она отражает то, что, по мнению вашей модели, делает человек на клавиатуре в соответствующем аудиофайле.

**Важно:** Отправляйте только файл `solution.csv`. Исходный код предоставлять не нужно. Файл должен содержать ровно одну строку для каждого аудиофайла в `test/`, при этом порядок значений `id` в `solution.csv` должен соответствовать порядку от `0` до максимального идентификатора.

## 5. Оценивание

- Ваши предсказания будут оцениваться с помощью **Macro F1 Score.**
- Macro F1 Score оценивает, насколько хорошо модель балансирует между точностью (precision) и полнотой (recall) для разных классов, при этом каждому классу придается равный вес. Модель может демонстрировать хорошие общие показатели, но при этом плохо справляться с редкими классами, что Macro F1 позволяет выявить.
- Решение, в котором каждой строке присваивается одно и то же значение, имеет показатель Macro F1 **менее** $0.5$.
- Итоговый балл по задаче в соревновании представляет собой показатель Macro F1, приведенный к шкале от $0$ до $100$ и округленный до двух знаков после запятой:

  $$
  \text{балл} = \text{Macro F1} \times 100
  $$

- Файл, который не удаётся прочитать, отклоняется из-за ошибки форматирования и не получает оценки. Это происходит в следующих случаях: количество строк не совпадает с количеством файлов в папке `test`; столбец `target` отсутствует или назван неверно; либо какое-либо значение в столбце `target` является пустым или не относится к одной из категорий: `coding` или `writing`.
- Балл, который вы видите во время соревнования, рассчитывается на основе $50\%$ тестовой выборки. Итоговый результат оценивается по оставшимся $50\%$ и будет объявлен после завершения соревнования.

## 6. Пример

**Вход (`train_labels.csv`):**

```
id,target
0,coding
1,coding
2,coding
3,writing
...
```

**Ваш ответ (`solution.csv`):**

```
id,target
0,writing
1,coding
2,writing
...
```

**Ограничение на посылки.** По каждой задаче можно отправлять не более одной посылки в минуту.
