## Есеп шарты

Әділхан мен Дархан дербес деректерді қорғау жүйесін әзірлеп жатыр. Құжаттарды өңдемес бұрын, жүйе ережелер жиынтығы мен аталған мәндерді тану (NER) моделінің көмегімен есімдерді, телефондарды, мекенжайларды және басқа да дербес деректерді бүркемелейді. Кейде жүйе дербес деректерді өткізіп алады. Қосымша тексеру үшін үлкен тілдік модельді пайдалануға болады, бірақ бюджет тек **құжаттардың 10 %-ына** ғана жетеді.

**Бағыттауыш (router)** әзірлеңіз: әрбір құжат үшін **тәуекел бағасын (risk score)** — қосымша тексеру басымдығы неғұрлым жоғары болса, соғұрлым үлкен болатын бір нақты санды беріңіз. Тексеруге ең жоғары бағасы бар құжаттар жіберіледі. Таңдалған 10 % ішіне өткізіп алулары бар құжаттар неғұрлым көп түссе, соғұрлым жақсы; **критикалық** дербес деректерге ерекше назар аударыңыз.

Бүркемелеуді түзетудің қажеті жоқ, тек басымдықтарды белгілеу талап етіледі.

### Санаттар

| Класс | Нені қамтиды |
|---|---|
| `USER` | аты, тегі, пайдаланушы аты |
| `ADDR` | ел, қала, облыс, аудан, көше және үй нөмірі, индекс, координаттар |
| `MAIL` | электрондық пошта мекенжайы |
| `TEL` | телефон нөмірі, факс нөмірі |
| `IBAN` | шот нөмірі, IBAN, SWIFT/BIC, routing-нөмірі |
| `DOC` | лицензия, сертификат, медициналық карта, полис нөмірі |
| `CARD` | банк картасының нөмірі, CVV |
| `IIN` | ЖСН, басқа ұлттық идентификатор, салық нөмірі |

Қарапайымдылық үшін ұқсас деректер түрлері бір класқа біріктірілген. **Критикалық кластар:** `IIN`, `CARD`, `TEL`, `MAIL`, `IBAN`. `has_critical_leak = 1` болса, `has_leak = 1` де болады.

**Өткізіп алу** — толығымен маскалармен жабылмаған (мәтінде толық немесе ішінара қалған) мән.

## Кіріс деректер форматы

JSON Lines, UTF-8, бір жолда бір объект.

| Өріс | Сипаттамасы |
|---|---|
| `document_id` | құжат идентификаторы |
| `lang` | `ru`, `kk`, `en` немесе `mixed` |
| `text` | бастапқы мәтін |
| `masked_text` | бүркемелеуден кейінгі мәтін: табылған әрбір мән `[КЛАСС]`-қа ауыстырылған |
| `cascade_entities` | **бүркемелеу жүйесі не тапты**: `start`, `end` (`text` ішіндегі символдық ығысулар, жартылай интервал), `type` (класс), `source` (`"rule"` немесе `"ner"`), `confidence` (NER сенімділігі немесе ережелер үшін `null`) бар объектілер массиві |
| `pii` | `start`, `end`, `label` бар **эталондық белгілеу** — тек `train.jsonl` ішінде |
| `has_leak`, `has_critical_leak` | 0/1 белгілері — тек `train.jsonl` ішінде |

**Екі массивті шатастырмаңыз:** `cascade_entities` — жүйенің болжамдары, олардың қателерін болжау талап етіледі; `pii` — эталон, тестілік таңдамада ол жоқ.

## Шығыс деректер форматы

UTF-8 форматындағы `predictions.csv`, тақырып жолымен:

```
document_id,risk_score
39703d9ea01c9e58,0.871
1a2b3c4d5e6f7890,0.014
```

Тесттің әрбір құжатына дәл бір жолдан, қайталауларсыз және белгісіз идентификаторларсыз болуы керек.
`risk_score` — нақты сан (бөлгіші — нүкте), `NaN` және `Inf` мәндеріне рұқсат етілмейді. Бағаның ықтималдық болуы міндетті емес: тек реті маңызды. Жолдардың реті еркін.

Форматқа сәйкес келмейтін файл **0 балл** алады.

Кіріс файлының екі жолы (мәтіндер қысқартылған):

```
{"document_id": "a1", "lang": "ru", "text": "Клиент Айгерим Сапарова, тел. +7 701 000 00 00.", "masked_text": "Клиент [USER], тел. [TEL].", "cascade_entities": [{"start": 7, "end": 23, "type": "USER", "source": "ner", "confidence": 0.97}, {"start": 30, "end": 46, "type": "TEL", "source": "rule", "confidence": null}]}
{"document_id": "a2", "lang": "kk", "text": "Байланыс: aigerim [at] mail [dot] kz, ЖСН 000000000000.", "masked_text": "Байланыс: aigerim [at] mail [dot] kz, ЖСН [IIN].", "cascade_entities": [{"start": 42, "end": 54, "type": "IIN", "source": "rule", "confidence": null}]}

Жауап:

```

Мысал тек форматты көрсетеді, ондағы бағалардың дұрыстығы тексерілмейді.

## Ескертпелер

**Құжаттарды іріктеу.** Тестте N құжат болған кезде, тексеруге ең жоғары бағасы бар `K = floor(0.1 × N)` құжат жіберіледі; N = 15 001 болғанда, бұл K = 1 500. Бағалар тең болған жағдайда, құжаттар `document_id` бойынша (жол ретінде) өсу ретімен реттеледі.

**Public / private.** Тур кезіндегі балл тестілік таңдаманың 30 %-ы бойынша есептеледі, ал қорытынды балл — қалған 70 %-ы бойынша есептеліп, турдан кейін жарияланады. Олар айтарлықтай ерекшеленуі мүмкін.

## Бағалау жүйесі

Белгілейік: **A** — `has_leak = 1` болатын тест құжаттары, **C** — `has_critical_leak = 1` болатын құжаттар, **S** — бағыттауыш таңдаған, бағасы ең жоғары K құжат. `|X|` жазбасы — құжаттар саны, `∩` — қиылысу.

```
R_all      = |S ∩ A| / |A|
R_critical = |S ∩ C| / |C|
score      = 100 × (0.5 × R_all + 0.5 × R_critical)
```

Екі көрсеткіш те бір ғана S жиынында есептеледі — критикалық өткізіп алуларға бөлек бюджет жоқ. Құжатта өткізіп алынған мәндердің санына қарамастан, құжат әр көрсеткіште бір рет есепке алынады. Максималды балл — 100.

**Мысал.** Тестте 10 000 құжат бар, тексеруге 1 000 құжат жіберіледі. Өткізіп алулары бар барлығы 200 құжат, оның ішінде 40-ы критикалық. Таңдалғандардың ішінде өткізіп алулары бар 140 құжат және критикалық өткізіп алулары бар 20 құжат болды:

```
R_all      = 140 / 200 = 0.70
R_critical =  20 /  40 = 0.50
score      = 100 × (0.5 × 0.70 + 0.5 × 0.50) = 60
```
**Шешім жіберу шектеуі.** Әр есеп бойынша минутына ең көбі бір шешім жіберуге болады.
