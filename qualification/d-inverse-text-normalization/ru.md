**Обратная нормализация текста** (inverse text normalization, ITN) — преобразование текста из произносимой формы в письменную. Распознаватель речи выдаёт произносимую форму, а читателю и всем последующим системам нужна письменная.

ITN работает с *семиотическими классами* — числами, датами, временем, денежными суммами, аббревиатурами, адресами и прочим, чья письменная форма отличается от произносимой:

```
двенадцать сорок пять           ->  12:45
он бес мың                      ->  15 000
айгуль собачка гмайл точка кз   ->  aigul@gmail.kz
кока кола                       ->  Coca-Cola
```

Прежде чем что-то преобразовывать, нужно решить, **какие слова вообще относятся к семиотическому классу и к какому именно**. Пропустишь спан — расшифровка останется нечитаемой. Разметишь лишний — получишь расшифровку, которая выглядит правильной и при этом неверна: система, превратившая обычное слово в число или в название, выдумала факт, и никто, кто прочитает расшифровку потом, этого не заметит.

В этой задаче вы делаете этот первый шаг — и только его.

Дано предложение в виде последовательности токенов. Нужно каждому токену приписать метку в формате **BIO**:

- `O` — токен не входит ни в один спан;
- `B-<CLASS>` — токен начинает спан класса `CLASS`;
- `I-<CLASS>` — токен продолжает спан, начатый предыдущим токеном.

*Спан* — максимальная группа подряд идущих токенов, которую человек записал бы одной записью одного класса. Такая разметка называется BIO и используется всюду, где из текста нужно выделить куски: имена, адреса, даты.

Классов восемь:

| класс | что это | что написал бы человек |
| --- | --- | --- |
| `CARDINAL` | количество | `15 000` |
| `ORDINAL` | порядковый номер | `17-й` |
| `DECIMAL` | дробное число | `1,5` |
| `DATE` | день месяца или год | `23-е` |
| `TIME` | время на часах | `5:30` |
| `MEASURE` | величина с единицей измерения — деньги и проценты тоже | `3 л`, `15 000 тенге`, `40%` |
| `EMAIL` | продиктованный адрес почты | `aigul@gmail.kz` |
| `WHITELIST` | имя, технический термин или аббревиатура | `Coca-Cola`, `attention`, `СМС` |

Письменные формы показаны, чтобы было понятно, *что* обозначает каждый класс; выводить их не нужно.

Метку определяет не само слово, а то, что стоит вокруг него. Во всех примерах ниже одно и то же слово — а в первом оно вообще не число:

```
адалдық ақыры бір көрінеді деп айтты
O       O     O   O        O   O
```

```
говорил двадцать   три        раза
O       B-CARDINAL I-CARDINAL O
```

```
встречаемся в три    тридцать
O           O B-TIME I-TIME
```

```
выйдем через три       минут
O      O     B-MEASURE I-MEASURE
```

```
мы используем ллама       три         в проде
O  O          B-WHITELIST I-WHITELIST O O
```

```
жүз       жиырма    келілік   қап
B-MEASURE I-MEASURE I-MEASURE O
```

Слово единицы измерения или валюты входит в спан; считаемый предмет — нет. Имена остаются снаружи.

## Формат входных данных

И в обучающей, и в тестовой выборке встречаются предложения трёх видов:

## Формат выходных данных

Отправьте один CSV-файл с именем `solution.csv`: заголовок и ровно одна строка на каждый токен `test.csv`, в любом порядке.

```
sent_id,token_id,label
s000000,0,O
s000000,1,B-TIME
s000000,2,I-TIME
```

Метка `I-`, не продолжающая спан того же класса, читается как начало нового спана.

**Важно:** отправляйте только файл `solution.csv`, исходный код не требуется. Решение не принимается, если для какого-либо токена `test.csv` строка отсутствует или встречается дважды, если колонка `label` отсутствует или названа иначе, а также если значение `label` не входит в множество допустимых меток.

## Оценивание

Решение оценивается метрикой **span-level F1 с точными границами**. Спан засчитывается верным, только если в ключе жюри есть спан с тем же первым токеном, тем же последним токеном и тем же классом. Частичное совпадение не даёт ничего.

Пусть `TP` — число верно найденных спанов, `FP` — число спанов вашего решения, которых нет в ключе, `FN` — число спанов ключа, которых нет в вашем решении. Тогда

```
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
F1        = 2 · precision · recall / (precision + recall)
```

При `TP = 0` считается `F1 = 0`. Балл за попытку — `100 · F1`, округлённый до двух знаков. Решение из одних `O` получает `0.00`, совпавшее с ключом — `100.00`.
